# Zeek Tunnel Log Analysis with Splunk

## Objective
Explore tunnel-related events from Zeek data and establish what additional evidence is needed to assess unusual activity.

## Dataset and Setup
- **Sample source:** [Security datasets — tunnel log](https://www.secrepo.com/maccdc2012/tunnel.log.gz)
- **Example sourcetype:** `tunnellog`
- **Index:** The example searches use `main`; change this to match your lab.
- Verify that the selected file contains the expected Zeek tunnel log format. Not all network datasets have the same fields.

## 1. Ingest and Validate
Upload the sample through **Settings → Add Data → Upload** and verify:

```spl
index=main sourcetype=tunnellog
| head 10
```

Review raw event structure, timestamps, and fields before relying on any extraction.

## 2. Discover Fields
```spl
index=main sourcetype=tunnellog
| fieldsummary
```

Use the actual schema. If fields such as `src_ip`, `dest_ip`, `tunnel_protocol`, or `action` are not present, create and test an appropriate extraction first.

## 3. Summarise Tunnel Events
If `tunnel_protocol` is available:

```spl
index=main sourcetype=tunnellog
| stats count by tunnel_protocol
| sort - count
```

## 4. Review Event Volume Over Time
```spl
index=main sourcetype=tunnellog
| timechart span=1h count
```

A time chart describes activity volume; it does not by itself establish malicious tunnelling. Compare results with the environment's expected protocols, hosts, and operational patterns.

## 5. Investigation Notes
For a completed investigation, document the dataset and fields, tested queries, relevant events, time range, unusual behaviour, alternative explanations, required corroboration, and next steps. Correlate with firewall, network-flow, DNS, and endpoint telemetry where available.

## Limitations
Tunnel protocols can be legitimate for administration, remote access, networking, or site-to-site connectivity. The log alone may not reveal payload intent or prove an incident.
