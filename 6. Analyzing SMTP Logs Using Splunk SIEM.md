# SMTP Log Analysis with Splunk

## Objective
Review SMTP transport activity and summarise patterns that may warrant further investigation.

## Dataset and Setup
- **Sample source:** [Security datasets — SMTP log](https://www.secrepo.com/maccdc2012/smtp.log.gz)
- **Example sourcetype:** `smtplog`
- **Index:** The example searches use `main`; change it to your lab index.
- SMTP log formats differ. Verify the event schema and available fields before running the example queries.

## 1. Ingest and Validate
Upload the file using **Settings → Add Data → Upload** and test:

```spl
index=main sourcetype=smtplog
| head 10
```

## 2. Discover Fields
```spl
index=main sourcetype=smtplog
| fieldsummary
```

Use the actual sender, recipient, response-code, and connection fields present in the sample. Create and test field extractions if needed.

## 3. Summarise Sender Activity
If the extracted sender field is `mail_from`:

```spl
index=main sourcetype=smtplog
| stats count by mail_from
| sort - count
| head 20
```

## 4. Review SMTP Activity Over Time
```spl
index=main sourcetype=smtplog
| timechart span=1h count
```

Use volume changes to find periods for review, not as conclusive evidence of spam or phishing.

## 5. Review SMTP Response Codes
If an extracted response code field called `smtp_reply_code` exists:

```spl
index=main sourcetype=smtplog
| stats count by smtp_reply_code
| sort - count
```

Interpret responses in the context of the server and event schema.

## Investigation and Limitations
Document the data source, schema, tested queries, sanitised results, interpretation, benign causes, and next steps. SMTP transport logs do not necessarily contain email body, attachment details, mailbox authentication events, or final delivery status. Use email gateway, authentication, or endpoint telemetry when those questions need to be answered.
