# HTTP Access Log Analysis with Splunk

## Objective
Review web-server access activity and identify unusual request patterns that may need investigation.

## Dataset and Setup
- **Sample source:** [Security datasets — HTTP log](https://www.secrepo.com/maccdc2012/http.log.gz)
- **Example sourcetype:** `httplog`
- **Index:** The searches use `main`; change it to the index you used during ingestion.
- Confirm the log format and available fields before relying on any query. Web access logs do not necessarily contain authentication or session information.

## 1. Ingest and Validate
Upload the sample through **Settings → Add Data → Upload** and confirm ingestion:

```spl
index=main sourcetype=httplog
| head 10
```

Inspect raw events, timestamps, and field extraction. If the search returns no events, verify the time range, index, and configured sourcetype.

## 2. Discover Fields
```spl
index=main sourcetype=httplog
| fieldsummary
```

Use the actual field names returned by your data. If the source format does not automatically extract fields, create and test an extraction appropriate for that format.

## 3. Summarise HTTP Status Codes
If `status_code` is available:

```spl
index=main sourcetype=httplog
| stats count by status_code
| sort - count
```

Review frequent 4xx and 5xx responses. These may indicate broken links, misconfiguration, scanning, or application errors; they do not automatically establish an attack.

## 4. Review Request Volume by Source
If `src_ip` is an extracted field:

```spl
index=main sourcetype=httplog
| stats count as requests by src_ip
| sort - requests
| head 20
```

Look for sources generating unusual volumes. Consider proxies, NAT, monitoring systems, crawlers, and expected client behaviour before treating a source as suspicious.

## 5. Review Requests Over Time
```spl
index=main sourcetype=httplog
| timechart span=15m count
```

Use this to locate periods for deeper review. Correlate any spike with status codes, requested paths, user agents, and other available logs.

## 6. Investigation Report
For a completed case, include:
- The investigation question and dataset source.
- The exact SPL query and fields used.
- Sanitised output or screenshots from your own run.
- A short timeline and interpretation of relevant events.
- Benign explanations, limits of the available data, and recommended follow-up.

## Limitations
Standard access logs may not contain usernames, session IDs, attachment details, or login results. Do not use queries based on fields that are absent from your dataset. A request pattern may be suspicious, but confirmation requires context and corroborating evidence.
