# FTP Log Analysis with Splunk

## Objective
Investigate FTP activity in a sample dataset and identify patterns that may warrant further review, such as repeated authentication failures or unusual file-transfer activity.

## Dataset and Setup
- **Sample source:** [Security datasets — FTP log](https://www.secrepo.com/maccdc2012/ftp.log.gz)
- **Splunk sourcetype used in examples:** `ftplog`
- **Index:** Replace `main` in the searches below if you imported the sample into a different index.
- **Important:** Sample formats vary. Check several raw events before using field extraction. These queries assume the selected dataset contains Zeek-style tab-separated FTP records; verify this before interpreting results.

## 1. Ingest and Validate
Upload the sample using **Settings → Add Data → Upload**. Set the index and sourcetype to match your setup, then verify events:

```spl
index=main sourcetype=ftplog
| head 10
```

Review `_raw`, `_time`, `host`, `source`, and `sourcetype`. If this returns no events, check the time range, index, and actual sourcetype.

## 2. Inspect Available Fields
```spl
index=main sourcetype=ftplog
| fieldsummary
```

Only use fields that exist in the dataset or that you explicitly extract. This repository uses `ftplog` as an example name; keep it consistent with your actual input configuration.

## 3. Explore FTP Command Activity
For Zeek-style FTP logs where `command` is extracted or available:

```spl
index=main sourcetype=ftplog
| stats count by command
| sort - count
```

This summarises observed commands. A high count is not, on its own, evidence of malicious activity.

## 4. Review FTP Activity Over Time
```spl
index=main sourcetype=ftplog
| timechart span=1h count
```

Use this to identify busy periods for follow-up. Investigate spikes in context, including maintenance, bulk transfers, and expected client activity.

## 5. Review File-Transfer Commands
If the dataset has an extracted `command` field:

```spl
index=main sourcetype=ftplog command IN (RETR, STOR)
| stats count by command
```

In common FTP command terminology, `RETR` typically indicates retrieval and `STOR` storage/upload. Confirm how the dataset represents commands before assigning this interpretation.

## 6. Investigation Notes
For an interview-ready case, record:
- What question you investigated.
- The source and structure of the sample data.
- The exact SPL query and any fields you extracted.
- Sanitised results from your own Splunk run.
- What the evidence supports, what remains uncertain, and likely benign explanations.
- What additional telemetry would help, such as authentication events, endpoint logs, or network-flow context.

## Limitations
FTP logs may not contain every detail needed to prove a successful transfer, identify a user reliably, or determine whether a file was malicious. Do not infer attachment contents, transfer size, authentication success, or user identity unless the dataset contains supporting fields.
