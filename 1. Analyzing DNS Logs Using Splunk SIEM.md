# DNS Log Analysis with Splunk

## Objective
Explore DNS query activity and identify unusual patterns for further investigation.

## Dataset and Setup
- **Sample source:** [Security datasets — DNS log](https://www.secrepo.com/maccdc2012/dns.log.gz)
- **Example sourcetype:** `dnslog`
- **Index:** The example searches use `main`; change it to the index used in your lab.
- Inspect several raw events before choosing field names. DNS logs differ by source, and fields such as `query`, `qname`, `fqdn`, or `src_ip` are not guaranteed to exist under those exact names.

## 1. Ingest and Validate
Upload the sample with **Settings → Add Data → Upload**, set the chosen index and sourcetype, and verify events:

```spl
index=main sourcetype=dnslog
| head 10
```

## 2. Discover Fields
```spl
index=main sourcetype=dnslog
| fieldsummary
```

Use the fields shown by Splunk or add a tested extraction for your dataset. The following examples assume that the stated fields have already been extracted.

## 3. Summarise Query Names
If the domain/query field is `qname`:

```spl
index=main sourcetype=dnslog
| stats count by qname
| sort - count
| head 20
```

This shows frequent query names. Popular domains, software updates, CDNs, and internal services can produce high counts; frequency alone is not proof of malicious activity.

## 4. Review Query Volume Over Time
```spl
index=main sourcetype=dnslog
| timechart span=15m count
```

Use the time chart to identify periods requiring more detailed inspection. Compare with a normal baseline where available.

## 5. Investigate a Query Name
After identifying a domain from actual results, replace `example.test` below with that value:

```spl
index=main sourcetype=dnslog qname="example.test"
| table _time src_ip qname query_type response_code
| sort 0 _time
```

Keep only fields that exist in your dataset. Reputation lookups may provide additional context, but a reputation result should be assessed alongside the event data rather than treated as conclusive on its own.

## 6. Investigation Report
Document the question, data source, index/sourcetype, fields and extractions, tested SPL, result evidence, time range, analyst interpretation, benign explanations, limitations, and next steps. Include screenshots only after reproducing the search in your lab.

## Limitations
The generic keyword search used in earlier versions did not reliably extract structured DNS fields. DNS frequency or an unfamiliar domain alone does not prove tunnelling or malware communication. More context—such as query types, response behaviour, client history, and endpoint telemetry—may be necessary.
